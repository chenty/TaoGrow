# 跨篇防撞车与防 AI 批量感（唯一权威定义）

> **本文件是"选择数 / 金句限频 / 开头冷却 / 去老X化 / 钩子轮换 / 结构轮换"六项规则的唯一权威定义。**
> 其他文件一律只引用、不重述。步骤 1.6 发现违规迹象时读本文件。
>
> 分工：本文件管"规则与判例"；逐篇状态由脚本读写工作目录的 `ledger_<账号名称>.json`（可选导出 `防批量登记_<账号名称>.md`）。

单篇看都合格、连读却像同一个人押韵——这是比"单篇 AI 味"更隐蔽的批量痕迹。两层都要防：

- **篇内**：固定清单排版 + 同位置加粗 → 平台判同质化、读者读出"AI 味"
- **篇间**：人物称呼、选择数量、钩子形态、结构骨架连续重复 → 老读者认出模子

**核心原则：保内核、换外壳。** 栏目辨识度靠"把读者拽进来问你怎么选"这个动作建立，不必靠固定排版长相。

---

## 一、六项纪律（速查表）

| 项 | 纪律与红线 | 违规典型 |
|---|---|---|
| **2. 人物称呼** | 严禁"老 X 列传"，**去老 X 化**；同名不同人亦严格禁止；近 5 篇禁用；优先身份代称、物件、台词或第二人称开场 | "老周"开工稿是朋友，花钱稿又成主角；9 篇里 8 篇"老X"开场 |
| **3. 选择数量** | 正文选择数在 **2–5** 之间定数，**相邻两篇强制不同**；**严禁连续两篇出现 5 选项**（高危形态） | 连续两篇都是 4 种活法；篇篇固定 3 种或固定 5 种 |
| **4. 结尾互动** | 四形态轮换（情境追问/生活经历/困境发问/开放填空），**与上一篇必须不同**；**严禁预设选项替读者说话** | 连续篇幅出现做题式 A/B 选项或扣数字，替读者预设立场 |
| **5. 结构骨架** | **每周至少 1 篇换结构**（纯对话体/时间线/一封回信/第一人称自述/清单反转），打破固定骨架；拓扑级轮换（T1–T6）与欠债账本自检见 references/hook-craft.md，两份叠加执行 | 篇篇都是"场景→身边两三个人→几种走向→金句→数字题" |
| **6. 金句与加粗** | 每篇"不是…是…""X靠A，Y靠B"对仗句**最多 1 句**；加粗节奏错开，允许某篇 0–1 处加粗、金句不加粗 | 篇篇"转折加粗 + 中段对仗金句加粗 + 结尾判断加粗"，像同一人在押韵 |

## 二、篇内做法（每篇必遵）

1. **选择段场景化**：不用"第一种/第二种/第三种"清单，改为"她身边的人各自给过答案"式叙述——选择逻辑和代价全保留，清单排版消失
2. **加粗密度减半**：不必每个选择首句都加粗；金句位错开，允许某篇全段无加粗
3. **篇间轮换**：句式、选择段位置（故事中段/结尾之间漂移）、选择数量刻意变化
4. **选择数量按排期表执行（重点）**：
   - 每篇动笔前在 **2–5 种之间定数**（掷骰、随机数均可，2/3/4/5 都要有机会出现）
   - **定数写入台账排期表**（如 3→5→2→4），相邻两篇强制不同；数量同时服从题材——素材天然只有两条路就写两条，不为凑数硬编第五条
   - **连续 5 选项属于高危形态**：结尾钩子与正文选择数都不得连续两篇用 5
5. **允许"不整齐"**：真人写作的选择段往往是歪的、带情绪的——某篇只有两句话、某条选择只写半句也完全可以

---

## 三、篇间做法（跨篇纪律）

7. **人物去"老X化"**：不要篇篇靠"老X"开场（会形成"老X列传"连续剧感）——改用身份代称（"一个开饭馆的""我表姐夫""楼下那个师傅"）、从物件或一句台词开场、或第二人称直接代入；同一称呼近 5 篇内不得复用，**同名不同人也不行**
8. **金句限频**：每篇对仗判断句**最多 1 句**，其余结论用大白话或一个具体动作收住；加粗节奏不得篇篇同构，允许某篇只有 0–1 处加粗、金句不加粗
9. **每周至少 1 篇换结构**：纯对话体 / 时间线 / 一封回信 / 第一人称自述 / 清单反转轮着来，打破"场景→我身边两三个人→几种走向→金句→数字题"的固定骨架
10. **样本不凑双**："我有个朋友甲乙"两个朋友举例也是套路；可换成自己的一件事深挖，或只留一个样本写透——每篇的人物样本数量也要变化

> **自检**：写完通篇看一眼，如果加粗全落在"金句位"、每段选择都加粗一次首句、**选择数量又是 3 或连着上一篇**、人物又是"老X"、对仗金句超过 1 句、排版太工整——回去打散它。
>
> ⚠️ 全号统一的文末引导语是品牌资产，**不属于批量痕迹，保留不改**。

## 四、台账机制

脚本：`scripts/ledger.js`（Node）／`scripts/ledger.py`（Python 等价，输出逐字节一致）

```bash
# Node 版把 node 换成 python3 即为 Python 版
node scripts/ledger.js check   <账号名称>   # 动笔前：查禁用清单与冷却状态
node scripts/ledger.js suggest <账号名称>   # 动笔前：推荐选择数/钩子形态/结构
node scripts/ledger.js log     <账号名称> --title "" --hook "" --choices N \
     --opening "" --opening-style "" --names "" --structure "" \
     --bold-count N --antithesis-count N --words N --tags ""
node scripts/ledger.js report  <账号名称>   # 分析分布 + 自检相邻重复违规
node scripts/ledger.js export  <账号名称>   # 导出 Markdown 台账供人工查看
```

**log 的必填参数**对应上面纪律：`--names`（人物称呼）、`--choices`（选择数）、`--hook`（钩子形态）、`--structure`（结构骨架）、`--antithesis-count` + `--bold-count`（金句与加粗）；`--opening` 可选，仅记录不参与校验。

## 五、结尾互动发问形态（不替读者说话、不预设做题选项）

> **核心原则：把表达权完整还给读者，绝不替读者预设立场或选项标签。**


| 形态 | 核心机制 | 示范 |
|---|---|---|
| **① 具体情境追问** | 把读者直接代入具体动作或瞬间，问其第一反应 | 「要是你，面对那条突然跳出来的和解消息，你会怎么回？」 / 「换成是你坐在那张桌子对面，你会开口吗？」 |
| **② 真实生活发问** | 唤起读者的相似经历与记忆，激发倾诉欲 | 「你身边也有这样走散很多年的人吗？后来还有交集吗？」 |
| **③ 代价与困境自问** | 抛出人际或金钱账中最纠结的核心矛盾 | 「在这件事上，你觉得最让人迈不过去的那道坎是什么？」 |
| **④ 开放填空留白** | 留下具体留白，让读者自主表达，不给任何预设标签 | 「如果用一句话给当年的这段关系画个句号，你会说什么？」 |

❌ 禁止空泛敷衍：“欢迎留言讨论”“你怎么看？”——无具体抓手。
❌ 严禁预设选项：“A…… B…… 留个字母”——把读者当做题工具，替读者预设答案，必须彻底弃用。

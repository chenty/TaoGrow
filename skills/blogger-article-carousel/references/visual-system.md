# 系列视觉系统与 handdraw-style-prompter 协作

## 必需依赖与职责边界

本 Skill 只负责确定系列视觉方向，并把它整理成**视觉 brief**。所有最终的生图提示词必须由 `handdraw-style-prompter` 生成：

- 本 Skill：确认平台、比例、系列统一规则、逐卡内容与文案、每页的视觉意图；
- `handdraw-style-prompter`：依据自身画风/图型/色彩图库、模型能力规则和参考图策略，为每张卡生成最终中英/中文图像提示词；
- 宿主的图片生成工具（若有）：使用依赖 Skill 返回的提示词与参考图，逐张生成图像。

不要在本 Skill 内维护另一套画风 ID、图型 ID、颜色 ID或完整图像提示词模板；不要把视觉 brief 直接改写成“最终提示词”。

调用依赖时：

1. 通过宿主技能系统调用技能名 `handdraw-style-prompter`。若没有技能调用按钮/接口，定位并完整读取它的 `SKILL.md`；如来自 `yang0/handraw-style`，保留完整仓库结构，先读根目录 `SKILL.md`，再读 `skills/handdraw-style-prompter/SKILL.md` 与其中要求的资料。
2. 逐张提交已经审核的卡片信息。让依赖 Skill 负责选择/核对有效图型、画风和颜色编号；用户指定的编号则原样传递，不擅自改号。
3. 确认依赖 Skill 返回的是每张卡独立的最终提示词。保持可见文案准确；不要自行追加、删改、翻译或重排依赖 Skill 生成的提示词。
4. 如需更改卡片文案、主题或视觉要求，先更新 brief，再请依赖 Skill 重新生成受影响卡片的提示词。
5. 如果依赖不可用，停在卡片文案与视觉 brief 阶段，告知用户需要启用 `handdraw-style-prompter`；不要用本文件的视觉 brief 代替最终出图提示词。

## 建立系列视觉 brief

在调用依赖 Skill 前，和用户确认或从对话中提取一组共用规则：

- 平台与画幅比例；
- 底色、主色、强调色与正文对比度（若有品牌色，优先遵守）；
- 标题/正文/注释的字体层级与安全边距；
- 插画媒材、线条、材质、阴影、颗粒度；
- 固定页码、角标、分隔符或重复视觉符号；
- 角色/IP是否存在，跨页外观是否一致；
- 禁用项（Logo、水印、额外日期、伪文字等）。

同系列不等于每页复制同一版式：固定色彩、字级、线条、间距和重复元素；根据每页内容调整图示结构与主视觉。视觉方向用可理解的风格描述，不自行制造画风编号。

## 传给 handdraw-style-prompter 的逐卡 brief

以下是交接资料，不是生图提示词。按卡片逐条传递：

- 平台、比例与系列视觉 brief；
- 本页在整组中的作用；
- 本页主题/核心信息；
- 已确认的准确可见文案（标题、正文、标签、原文引用）；
- 视觉意图（图示类型或隐喻，不增加文章外事实）；
- 用户指定的画风、图型、主题色编号（如有）；
- 必须保留/不得出现的内容。

让 `handdraw-style-prompter` 自己解析该 brief、选择有效编号并生成最终提示词。不要把多张卡塞进一条提示词，也不要绕过其图文模式、参考图和模型能力规则。

## 文字与图片质量

- 用户确认的卡片文案是唯一可见文字来源；依赖 Skill 应在其规则内处理图文关系。
- 若宿主具备可靠的 SVG/HTML/排版能力，可在依赖 Skill 提示词之后，将插画与准确文字分层排版；此时不改写依赖 Skill 的提示词语义，也要用其参考图规则。
- 如果直接用图像模型渲染文字，逐张检查错字、漏字、乱码、重复句、额外日期/标签、Logo 与水印。发现问题时将修正需求交给依赖 Skill，并再次生成提示词/图片；未校对的结果不得称为无误稿。
- 一页一个文件，不生成多页拼图/九宫格。

## 导出与命名

- 画幅按用户确认的平台规格；用户授权 Agent 决定时，明确写出采用的比例。
- 文件名按发布顺序：`01-cover.png`、`02-context.png`、`03-framework.png` 等；名称可按内容调整。
- 若可用，交付单张 PNG/JPG、合并浏览 PDF、打包 ZIP 与独立文案文件。
- 高精度需求可同时交付可编辑 SVG/HTML/设计稿；只交付实际制作出的格式。
